# ContextFlow 评测协议、指标与复现指南

## 1. 目标与原则

本评测体系回答三类问题：

1. **快**：ContextFlow 对本地结构化任务的端到端完成时间、工具调用成本和上游兜底情况如何；
2. **准**：状态、Agent、工具、RAG 证据和最终任务结果是否正确；
3. **狠**：是否覆盖多场景、支持跨 Agent 工作流，并在确认、隔离、撤销和异常情况下保持安全。

所有正式对比遵循以下原则：同一设备、同一 OpenClaw 版本、同一上游模型和版本、同一固定测试资料、相同超时设置；每轮使用新的 session 与独立临时目录。奇数轮按 Native → ContextFlow，偶数轮按 ContextFlow → Native 执行，以降低先后顺序造成的偏差。

## 2. 测试集

### 2.1 ContextFlow 专项 Benchmark：9 个确定性 Case

入口：`benchmark/runner.py`。

| 场景 | Case | 成功条件 |
|---|---|---|
| 会议交付 | `meeting_deadline_v1` | 会议文件事件触发、升级为 `deadline_risk`、仅产生一份会议草稿和一份交付草稿 |
| 会议交付 | `meeting_no_deadline_v1` | 没有明确数值期限时停留在 `meeting_ended`，不超前生成交付计划 |
| 会议交付 | `meeting_duplicate_event_v1` | 同一文件重复到达时，不新增事件和草稿 |
| 数据洞察 | `data_risk_v1` | 识别预置异常并生成 SVG 图表 |
| 数据洞察 | `data_arrival_state_v1` | 数据文件稳定到达后进入 `data_ready_for_analysis` |
| 数据洞察 | `data_session_isolation_v1` | 其他 session 不能读取已导入的数据集 |
| 桌面执行 | `desktop_archive_v1` | 确认后归档，撤销后恢复原文件 |
| 桌面执行 | `desktop_unapproved_block_v1` | 未确认时执行被拒绝且文件不移动 |
| 桌面执行 | `desktop_path_escape_v1` | 拒绝 `../` 等超出根目录的路径 |

这是 Runtime 确定性回归集，不含在线模型随机性。每个 Case 应至少重复 3 次。

### 2.2 端到端 A/B 测试集

入口：`benchmark/ab_runner.py`。

| Case | Native 组 | ContextFlow 组 | 评测目标 |
|---|---|---|---|
| `file_search` | OpenClaw 直接调用同一上游模型与等价文件工具 | OpenClaw → MTClaw → DesktopExecutorAgent | 通用只读文件检索能力及端到端延迟 |
| `local_rag` | 同一临时资料文件、等价本地读取能力 | 同一资料先导入 session-local RAG，再回答 | 有来源的本地知识问答、会话隔离与准备成本 |
| 后续 `data_insight` | 同一 CSV、等价读取/分析能力 | DataInsightAgent | 风险识别与图表产物 |
| 后续 `desktop_archive` | 同一临时目录 | DesktopExecutorAgent | 确认边界、执行与撤销 |

本地 RAG 题库位于：

- `benchmark/fixtures/rag/contextflow_reference.md`；
- `benchmark/fixtures/ground_truth/rag_questions.json`。

题库当前包含 10 个固定问题，覆盖 Runtime 分工、上游兜底、确认边界、状态升级、跨 Agent 编排、去重、数据能力、会话隔离、归档安全和能力边界。每题有必须出现的事实要点和来源文件名。

> 注意：`local_rag` 的 ContextFlow 路径包含“资料导入 + 问答”两个回合，因此报告会拆分知识准备、纯问答和端到端时间；不能与 Native 的单回合“直接读文件”延迟混为同一结论。

### 2.3 外部通用 Benchmark

| Benchmark | 使用方式 | 在材料中的作用 |
|---|---|---|
| OpenClaw ShellBench（原 ClawBench） | 精选文件、数据、记忆、任务规划相关任务，至少每项 3 次 | 验证执行轨迹、失败恢复、工具循环与稳定性 |
| PinchBench | 精选文件、日程、数据、知识检索、记忆相关任务 | 验证接入 Runtime 后的通用 Agent 能力不显著退化 |

外部 Benchmark 仅报告实际完成的 **selected task subset**；不可将精选任务的结果表述为完整榜单成绩。

## 3. 指标定义

### 3.1 快：时延与成本

| 指标 | 定义 | 采集位置 |
|---|---|---|
| 端到端任务完成时间 | 从 A/B 请求发出到最终回答或可验证产物完成的总时间 | `latency_breakdown_ms.end_to_end` |
| 知识准备时间 | RAG 导入资料所需时间 | `latency_breakdown_ms.preparation` |
| 纯问答时间 | 资料准备完成后的问答耗时 | `latency_breakdown_ms.question` |
| P50 / P95 | 同一 Case 多次重复的中位数 / 最近秩 95 分位 | A/B 与专项 JSON 报告 |
| 工具调用数 | Router Trace 优先，否则用响应中工具调用数 | `tool_calls` |
| 工具成功率 | 成功工具执行数 / 工具总执行数 | SQLite `execution_events.success`；Router `tool_error_count` |
| 上游兜底率 | 至少一次 fallback 的轮数 / 总轮数 | `fallback_rate` |
| Token 使用量 | 响应与 Router Trace 中可用的 Token 统计 | `usage`、`response_usage`、`router_usage` |

只有在 Native 与 ContextFlow 的任务目标、模型、工具能力和输入等价时，才能报告加速比：

```text
加速比 = Native P50 端到端时间 / ContextFlow P50 端到端时间
```

若 ContextFlow 多了导入、确认、撤销等额外工作，应同时报告“端到端时间”和“同一阶段的纯执行/纯问答时间”，不可只选对自己有利的口径。

### 3.2 准：效果与可靠性

| 指标 | 定义 |
|---|---|
| 任务完成率 | `outcome_verified=True` 的轮数 / 总轮数 |
| 全轮通过率 | 同一 Case 是否每次重复均通过；用于稳定性展示 |
| 状态识别准确率 | 目标状态命中次数 / 有标签事件数 |
| 误升级率 | 不满足转移条件却进入高优先级状态的次数 / 不应升级样本数 |
| Agent/工具选择正确率 | 选择命中预先标注 Agent/工具路径的次数 / 总样本数 |
| RAG 事实要点命中率 | 必须要点和来源文件均满足的题数 / 总题数 |
| RAG 无证据安全率 | 无证据题中明确说明证据不足、未补造事实的次数 / 无证据题数 |
| 数据风险精确率 / 召回率 | 预置风险集合与检测风险集合的 Precision / Recall |
| 工具调用成功率 | 成功工具执行数 / 工具总执行数 |

### 3.3 狠：覆盖、长链路与安全

| 指标 | 定义 |
|---|---|
| 场景覆盖数 | 已可运行的独立工作场景数量；当前为会议、数据、桌面三类 |
| 专用 Agent 数 | 已注册 Agent Manifest 数；当前为 6 个，数量不单独代表系统能力 |
| 长链路编排通过率 | 会议 → Pipeline 节点 → 唯一草稿/预期产物的通过率 |
| Checkpoint 恢复成功率 | 在指定节点中断后，从最近 Checkpoint 恢复并完成且不重复已完成副作用/草稿的次数 / 注入中断次数 |
| Operation 幂等率 | 同一 Task 与幂等键重放时未重复执行副作用的次数 / 重放次数 |
| 旧计划审批拦截率 | 已重规划或已 supersede 的计划绑定审批在执行前被拒绝的次数 / 应拒绝次数 |
| 幂等去重率 | 重复事件未产生新增草稿的次数 / 重复事件测试次数 |
| 确认边界遵守率 | 未确认外部/桌面写操作被成功拦截的次数 / 应拦截次数 |
| 撤销恢复率 | 已执行归档被撤销并恢复正确文件内容的次数 / 撤销测试次数 |
| 会话隔离率 | 跨 session 访问被阻止的次数 / 跨 session 尝试次数 |

## 4. 日志与审计证据

### 4.1 可提交的脱敏报告

`benchmark/reports/` 中每次运行生成：

- `contextflow-benchmark-*.json/.md`：9 项专项 Benchmark；
- `unified-ab-*.json/.md`：A/B 端到端报告。

A/B JSON 按轮保留：Case、顺序、隔离 session key、最终回答、任务是否通过、完整端到端时间、时间拆分、工具调用数、工具轮数、错误数、兜底数、Token、文件快照差异、验证失败原因和脱敏 Router Trace 摘要。

### 4.2 本机私有全量审计记录

为保护真实文件路径、会议内容和密钥，以下记录只在本机保存，不直接上传至比赛材料：

| 记录 | 位置 | 内容 |
|---|---|---|
| ContextFlow Runtime 审计 | `data/contextflow.db`，`execution_events` 与 `runtime_*` 表 | session、状态、Agent、工具、Task/Execution、Checkpoint、Operation、Approval、Trace、结果和错误 |
| 状态证据 | 同一 SQLite 的 `sensed_events`、`state_transitions` | 事件来源、证据、置信度、状态转移 |
| Router 工具历史 | `http://127.0.0.1:18791/v1/tool_history?limit=200` | Provider 侧工具调用、工具结果、轮数、模型/兜底信息（以实际 Router 配置为准） |
| Router 调试日志 | `mtclaw/logs/router.debug.log` 或部署环境指定日志目录 | 路由决策、调用顺序、错误与 fallback |
| OpenClaw 会话记录 | `~/.openclaw/agents/<agent>/sessions/` | 完整用户/Agent 对话与会话映射（私有） |

专项 Runtime 会将完整工具结果与生命周期记录写入 SQLite；A/B 报告只保留 Router 工具名称和统计，不复制工具参数与结果，以避免报告中泄露文件内容或凭据。若评委需要核验，应现场展示本机私有审计记录或经过人工脱敏的导出片段。

### 4.3 导出与检查命令

检查 ContextFlow Dashboard：

```powershell
& ".\ContextFlow\.venv\Scripts\python.exe" ".\ContextFlow\service\runtime_dashboard.py"
```

浏览器打开 `http://127.0.0.1:8765`；可附加 `?session_key=<session_key>` 查看指定运行。

获取 Router 最近工具历史（Windows PowerShell）：

```powershell
Invoke-RestMethod "http://127.0.0.1:18791/v1/tool_history?limit=200" |
  ConvertTo-Json -Depth 20 |
  Set-Content -Encoding UTF8 ".\private-router-trace.json"
```

`private-router-trace.json` 仅用于本机核验；上传或展示前必须删除 API Key、Token、个人路径、会议原文、工具参数和完整工具结果。

## 5. 复现步骤

### 5.1 环境固定记录

每次正式运行前记录：

```text
日期与时区
设备型号、CPU/GPU、内存、操作系统
Python / Node / OpenClaw / MTClaw / ContextFlow 版本或 Git SHA
Native 与 ContextFlow 的模型名、模型版本、temperature、max tokens、timeout
是否本地模型、网络模型或混合模式
测试 Case、fixtures 的 SHA256、重复次数
```

密钥和 Gateway Token 不应记录到报告中。

### 5.2 运行 9 项专项 Benchmark

在项目根目录运行：

```powershell
cd "C:\Users\Lenovo\Documents\摩尔线程个人工作智能体"

& ".\ContextFlow\.venv\Scripts\python.exe" ".\ContextFlow\benchmark\runner.py" --runs 3
```

保存终端输出的报告路径，并归档对应 JSON 和 Markdown。

### 5.3 运行 A/B 文件搜索

确保 OpenClaw Gateway 和 MTClaw Router 已启动，私有 Gateway 配置可用。然后：

```powershell
cd "C:\Users\Lenovo\Documents\摩尔线程个人工作智能体\ContextFlow"

& ".\.venv\Scripts\python.exe" -m benchmark.ab_runner `
  --config "$env:USERPROFILE\.config\contextflow\gateway-benchmark.json" `
  --case file_search --runs 3
```

### 5.4 运行 A/B 本地 RAG

```powershell
cd "C:\Users\Lenovo\Documents\摩尔线程个人工作智能体\ContextFlow"

& ".\.venv\Scripts\python.exe" -m benchmark.ab_runner `
  --config "$env:USERPROFILE\.config\contextflow\gateway-benchmark.json" `
  --case local_rag --question-id rag_runtime_roles_v1 --runs 3
```

对每个固定问题重复上述命令。建议先完成 5 个核心问题：

```text
rag_runtime_roles_v1
rag_confirmation_v1
rag_meeting_trigger_v1
rag_session_isolation_v1
rag_scope_boundary_v1
```

## 6. 结果展示模板

### 6.1 快、准、狠证据矩阵

| 维度 | 指标 | 数据来源 | 报告时的口径 |
|---|---|---|---|
| 快 | P50/P95 端到端时间、工具数、兜底率 | A/B JSON、Router Trace | 仅在等价任务中比较 Native 与 ContextFlow |
| 准 | 完成率、状态/路由正确率、RAG 引用命中率 | 专项 JSON、RAG 题库、外部 Benchmark | 逐项给出分母、重复次数和失败原因 |
| 狠 | 场景、长链路、恢复、幂等、版本审批、安全/撤销/隔离率 | 9 项专项 Benchmark、Runtime 回归、Demo、审计日志 | 展示覆盖面与真实可交付边界 |

### 6.2 最低报告要求

每个对外表格应至少写明：测试版本、设备、模型、Case 数、每项重复次数、成功判定规则、统计口径和报告生成时间。

没有完成 A/B 的指标请写“待测”，不要以专项 Runtime 的毫秒耗时替代模型端到端时间；没有真机复测的数据不得表述为 MTT AIBOOK 性能结论。
